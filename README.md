# 小智 ESP32 私有音乐播放服务 (Xiaozhi Private Music MCP Server)

本项目为 **小智 AI 语音助手（ESP32）** 提供了本地私有音乐曲库点歌与播放的完整解决方案。通过接入模型上下文协议（**MCP, Model Context Protocol**），让小智大模型能够理解用户的点歌、查歌单、随机播放等自然语言指令，并通过小智底层原生语音通知（`notify`）协议播放本地局域网的高品质音乐文件。

## 一、 实现原理与系统架构

### 1. 整体交互流程

```text
[用户口述点歌] -> 例如："我想听周杰伦的晴天"
       │
       ▼
[小智 ESP32 硬件] ────(Opus 语音上传)────> [小智云端大模型 (LLM)]
                                                │
                                      (命中意图，发起 MCP Tool 调用)
                                                ▼
                                    [小智云端 MCP 网关 (WSS)]
                                                │
                                    (经 WebSocket 双向桥接传输)
                                                ▼
                                         [mcp_pipe.py]
                                                │ (stdio 管道)
                                                ▼
                                         [xzmcp.py (FastMCP)]
                                                │
                                    (查询曲库并生成 notify 协议报文)
                                                ▼
[小智 ESP32 硬件] <──(下发 notify 报文)── [小智云端控制通道]
       │
 (读取到 audio_url: http://192.168.50.220:8111/qingtian.ogg)
       │
       ▼
[ESP32 启动后台 HTTP Task] ────> [本地 HTTP 文件服务 (8111端口)]
       │                                     │
       │<─────────(分块下载 Ogg 音频流)─────────┘
       ▼
[ESP32 底层 OggDemuxer 解包] ──> [esp_opus_dec 解码为 PCM] ──> [扬声器放音 + 屏幕显示歌名]
```

### 2. ESP32 底层音频播放限制揭秘

许多开发者尝试直接给小智传入 `.mp3` 链接，结果设备完全静音，这是由小智 ESP32 原生固件底层架构决定的：
1. **无 MP3 解码器**：小智 ESP32 固件为节约 RAM 与 Flash，仅集成了 `esp_opus_dec`（Opus 解码器），并未打包 MP3/AAC 解码库。
2. **强制校验 Ogg Opus**：小智处理 `notify` 的音频解包器 `OggDemuxer` 仅识别 `OpusHead` 标志，**且强行拦截非单声道（Stereo 双声道会直接抛出错误并退出）**。
3. **无重定向跟随**：ESP32 的轻量级 HTTP 客户端不跟随 301/302 重定向，必须是直接返回 `200 OK` 的真实直链。

因此，**本工程所有音乐文件均转码为严格符合小智硬件标准的单声道 16kHz Opus 编码 `.ogg` 文件**，并通过本地轻量 HTTP 服务器提供直接下载，确保百分之百出声。

## 二、 目录文件说明

| 文件名 | 作用与功能说明 |
| :--- | :--- |
| **`xzmcp.py`** | **MCP 核心服务**。基于 `FastMCP` 实现，注册了 `play_my_music`（指定点歌）、`list_music_library`（查歌单）、`play_random_music`（随机播放）三个工具。 |
| **`mcp_pipe.py`** | **WSS 桥接脚本**。将小智官方云端 MCP 网关（WebSocket）与本地运行的 Python MCP 进程（stdio）通过标准输入输出进行双向穿透通信。 |
| **`start_services.bat`** | **一键启动批处理脚本**。双击即可在后台同时拉起 HTTP 音频文件服务（8111端口）以及 MCP 桥接服务。 |
| **`新建文本文档.txt`** | 存放从小智后台（xiaozhi.me）复制的 `MCP_ENDPOINT` 接入端点环境变量链接。 |
| **`*.ogg`** | 符合小智 ESP32 播放标准（16kHz Mono Opus）的音频文件。 |
| **`*.mp3`** | 原始音乐备份文件（不可直接传给未修改的小智固件）。 |

## 三、 环境准备与依赖

1. **Python 环境**：Python 3.10 或更高版本。
2. **安装 Python 依赖库**：
   ```bash
   pip install fastmcp websockets ffmpeg-python
   ```
3. **系统依赖**：
   电脑需安装有 `ffmpeg` 命令行工具（用于音频批量转码）。可通过终端运行 `ffmpeg -version` 检查是否安装。

## 四、 音乐音频准备与转码 (关键)

若曲库中新增了 `.mp3` 歌曲，**必须先转码成小智专属的 Ogg Opus 格式**。

### 转码命令（终端直接执行）：
```bash
ffmpeg -y -i input.mp3 -c:a libopus -b:a 16k -ac 1 -ar 16000 -frame_duration 60 output.ogg
```
**关键参数说明**：
* `-c:a libopus`：指定使用 **Opus** 音频编码器。
* `-ac 1`：强制转换为 **单声道 (Mono)**（重要！双声道会导致小智静音）。
* `-ar 16000`：采样率设置为 **16kHz**。
* `-b:a 16k`：音频码率设为 **16kbps**（兼顾带宽与人声/音乐清晰度）。
* `-frame_duration 60`：Opus 帧长设为 **60ms**（匹配小智固件配置）。

### 更新曲库配置文件：
在 `xzmcp.py` 的 `MUSIC_LIBRARY` 字典中添加新歌信息：
```python
MUSIC_LIBRARY = {
    "晴天": {
        "url": "http://192.168.50.220:8111/qingtian.ogg",
        "artist": "周杰伦",
        "genre": "流行"
    },
    # 在此追加新歌 ...
}
```
*(注：请确保将 IP 地址替换为您当前主机的局域网 IP)*

## 五、 服务配置与启动

### 1. 配置 MCP WSS 端点
1. 登录 [小智控制台 (xiaozhi.me)](https://xiaozhi.me/)。
2. 进入您的设备角色配置 -> **MCP 工具** 配置界面。
3. 复制生成的 **接入点端点 URL**（形式为 `wss://api.xiaozhi.me/mcp/?token=...`）。
4. 将该链接粘贴并更新至 `start_services.bat` 和 `新建文本文档.txt` 中。

### 2. 一键启动服务
直接双击运行目录下的：
```text
start_services.bat
```
脚本将依次启动：
1. **音乐 HTTP 服务**：在 `0.0.0.0:8111` 监听，供局域网内的小智下载播放音乐。
2. **MCP 桥接服务**：连接小智云端，自动注册 `play_my_music` 等 3 个点歌工具。

控制台打印如下信息表示运行正常：
```text
[SUCCESS] [mcp-pipe] WSS 连接成功！MCP 工具已注册到小智云端。
```

### 3. 小智云端管理后台 (xiaozhi.me) 配置
为了确保大模型准确调用点歌工具，在后台的角色 **Prompt（人设设定 / 人物介绍）** 中追加以下引导词：
> **“你具备音乐播放能力。当用户提出听歌、点歌、播放音乐或询问歌单等需求时，请调用专属的 MCP 音乐工具（play_my_music、list_music_library 或 play_random_music）。在播放歌曲时，请自然友好地告知用户正在播放的歌名和歌手。”**

## 六、 常见问题与排查排障 (FAQ)

### Q1: 点歌后小智说“正在为您播放”，但小智喇叭没有出声？
请按以下顺序排查：
1. **局域网连通性**：
   * 确保小智连接的 Wi-Fi 与运行本程序的电脑处于**同一台路由器的同一个局域网网段**（如 `192.168.50.x`）。
2. **Windows 防火墙拦截 8111 端口**：
   * 用同一 Wi-Fi 下的手机浏览器打开 `http://192.168.50.220:8111/qingtian.ogg`。
   * 如果手机打不开或一直转圈，说明 Windows 防火墙拦截了外来入站连接。可在 Windows Defender 高级安全防火墙中将 `8111` 端口加入允许入站规则。
3. **音频文件是否为单声道 Opus**：
   * 必须是通过上述 `ffmpeg` 命令生成的 `.ogg` 文件，直接将 `.mp3` 文件后缀改名为 `.ogg` 是无法播放的。

### Q2: 电脑重启后局域网 IP 发生变动？
1. 在电脑命令行运行 `ipconfig` 查看当前新的无线局域网 IPv4 地址。
2. 如有变动，请在 `xzmcp.py` 中批量替换 `MUSIC_LIBRARY` 中的 IP 地址。

### Q3: 为什么不需要在 ESP32 上编写额外的 C++ 解码插件？
因为本项目巧妙利用了小智原生固件的 `notify` 机制。小智官方在 `application.cc` 和 `notify_player.cc` 中原本就自带了一套通过 HTTP 增量拉取单声道 Ogg Opus 并在解码后推送到 I2S 扬声器的管道。我们直接复用其官方机制，不仅兼容性最好，而且不需要重刷或二次魔改固件。
